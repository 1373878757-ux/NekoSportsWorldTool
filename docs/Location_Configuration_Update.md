# 可自行更新的定位配置

日期：2026-11-09。基于现有 `feature/j-claude-cross-platform` 分支增量修改。

## 问题与修正

原页面仅支持手工填写城市与坐标。更改城市不会自动更改锚点，因此可能保存出“哈尔滨市 + 历史大连默认坐标”的配置。现有校验还会单独拒绝“大连市”这个城市名，即使用户已填写另一组合法坐标。

本次增加用户可自行反复使用的“获取当前位置”入口，并移除单独按“大连市”城市名拒绝配置的条件。原历史默认坐标识别、城市非空、经纬度范围及有限值检查继续保留。城市名并非地理编码结果，本地格式校验也不能证明用户实际位于该城市。

## 使用方式

1. 打开“设备信息”，点击“获取当前位置”。
2. 默认浏览器打开本机定位页，点击“授权并获取当前位置”，按系统与浏览器提示允许定位。
3. 返回软件，查看回填的坐标与精度；核对或修改城市名称，点击“保存”。
4. 更换地点后，可再次获取并保存；仍可手动填写 BD-09 纬度、经度。

系统定位不提供本实现可直接使用的城市名，因此本次不自动反查城市。获取失败、拒绝授权或精度较低时，页面提供原因与人工核对提示。软件保留已有配置，用户也可以直接手工编辑。保存与重新加载继续使用原 `identity.json` 机制。

## 实现与边界

| 文件 | 内容 |
| --- | --- |
| `src/location_acquisition.rs` | 一次性本机回传服务、输入校验、过期检查、取消与超时、WGS84 输入适配 |
| `src/location_acquisition/tests.rs` | 合成位置、一次转换、权限/超时错误、本机 HTTP 回传约束、离线与取消测试 |
| `assets/location/authorize.html` | 内嵌本机页面；由用户点击后调用浏览器 `getCurrentPosition` |
| `src/ui/device.rs` | 获取/取消入口、回填编辑框、精度与来源说明、手动修改保护、显式保存测试 |
| `src/ui/mod.rs` | 接收定位完成结果；后台完成时唤醒 GUI |
| `src/lib.rs` | 仅在 GUI feature 下编译定位入口 |
| `src/crypto/header.rs` | 修正单独拒绝“大连市”的本地校验及相应回归断言；网络身份字段与协议不变 |

浏览器提供 WGS84。沿用项目对平台锚点/地图的 BD-09 工作约定，在输入边界转换一次，回填编辑框；原始 WGS84 与定位时间仅用于当前进程的来源/精度状态。转换后数值仍需通过现有坐标合法性检查。

结果先进入未保存的编辑缓冲区。用户点击保存成功后才更新已生效身份。定位期间手工修改坐标时，迟到结果不覆盖输入；取消、保存、撤销或关闭应用会终止待处理定位。获取失败不清空旧值。

回传服务只监听 `127.0.0.1` 随机端口，每次使用独立随机路径，校验 Host、Origin 与 JSON 类型，限制请求大小，并设置页面 CSP、禁止缓存和引用来源泄露。一次结果后关闭；等待授权的总期限为 120 秒，浏览器单次定位期限为 20 秒，没有自动重试或连续追踪。后台等待不阻塞 GUI，结果就绪后唤醒界面。

页面通过默认浏览器运行，不引入 WebView、Electron、原生定位绑定或新的 Cargo 依赖。浏览器及系统的定位服务可能需要网络；用户在页面中主动授权。`NSWT_OFFLINE=1` 下禁用定位入口，并在服务入口再次拦截，保留手动配置。

没有改写当前真实用户配置，没有登录、调用运动提交或修改业务时段限制。原 `11016` 平台业务限制不属于本次修正范围。
